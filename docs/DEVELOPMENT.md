# 💻 开源版部署指南

本文面向想在微信开发者工具里**自行部署**拾光开源演示版的开发者。你不会获得原线上应用的 AppID、云开发权限、用户数据或 AI 额度。

## 前置条件

- 微信开发者工具和一个可用于开发的微信小程序 AppID
- 自己开通的微信云开发环境
- 如需体验 AI 生成：自行开通并获准使用相应模型服务
- Node.js（可选，用于运行本地测试）

## 1. 获取项目

```bash
git clone https://github.com/liujiayiwzl/shiguang-miniapp-open-source.git
```

在微信开发者工具中选择**导入项目**，目录指向克隆得到的项目根目录。

## 2. 替换示例环境标识

- 编辑 `project.config.json`，将 `appid` 从 `touristappid` 改为自己拥有的 AppID。
- 编辑 `app.js`，把 `YOUR_CLOUDBASE_ENV_ID` 改为自己的云开发环境 ID。
- 不要将私钥、AppSecret、付费 API Key、生产环境信息或 OpenID 添加到公开仓库；建议 fork 后自行管理配置，勿推送真实敏感信息。

> AppID、环境 ID 通常不是账号密码，但也不应该让演示项目默认连接他人的线上环境。真正需要保护的密钥绝不能写入小程序客户端源码。

## 3. 配置数据库

在**你自己的云开发环境**中创建下列集合，按实际业务设置安全规则与索引：

| 集合 | 作用 |
| --- | --- |
| `cards` | 公共、私有卡片与审核状态 |
| `favorites` | 用户收藏 |
| `ai_usage` | AI 创作频次控制 |
| `wordProfiles` | 每日学习目标 |
| `wordDaily` | 每日学习与打卡 |
| `wordRecords` | 单词作答记录 |

云端可选词库相关 `wordBanks`、`wordItems` 集合不是本地演示词库运行的前置条件。数据访问应由云函数根据微信 `OPENID` 校验，不要将用户数据集合设置为全员可写。

## 4. 部署云函数

在微信开发者工具中找到 `cloudfunctions/`，按需逐个右键 **上传并部署（云端安装依赖）**：

- `getLibraryCard`：按主题获取审核通过的卡片
- `getCard`：获取指定卡片
- `generateCard`：AI 创作（需要自行准备模型服务）
- `favoritesApi`：收藏管理
- `saveCard`：卡片保存
- `wordsApi`：学习记录与云端同步

如果云开发环境或调用权限未配置正确，首页卡片及云端功能可能无法使用。请优先查看微信开发者工具控制台和对应云函数日志。

## 5. 测试单词学习

`packageWords/data/wordbanks/` 含 `junior.js`、`senior.js`、`cet4.js`、`cet6.js`，每个文件各 12 条手工整理的演示数据。通过“打卡 → 选择词库 → 翻卡 / 四选一”检查交互。

英式、美式发音引用外部音频接口，真机使用需核对第三方服务授权，并在微信后台配置相应的合法下载域名。接口可能变化，不保证长期可用。

## 6. 本地测试

已有两个 Node.js 测试脚本，使用内存数据库而非真正云环境：

```bash
node scripts/test-words-api.js
node scripts/test-word-sync.js
```

在线上开放 AI 生成功能前，请另外核对模型额度、生成内容审核与标识、用户隐私以及账号主体可用服务类目。开源许可并不等于获得微信平台发布资质。

## 7. 常见问题

- **提示无法调用云函数**：先核查环境 ID、函数部署、函数权限与网络。
- **只能看到 12 个演示词**：这是开源版刻意使用的示例数据，不包含正式词库。
- **AI 失败**：先核对模型服务权限与费用额度，不要把生产密钥硬编码在前端。
- **能在 GitHub 直接运行吗**：不能。需要微信开发者工具与微信运行环境；普通微信用户应通过[线上体验指南](EXPERIENCE.md)使用已经上线的版本。
